Q6. Deploying a containerized application (10 marks · CO2 · PO4)

(a) The orders API below must:

  • run four replicas
  • be updated without downtime
  • receive traffic only once a Pod is ready to serve
apiVersion: apps/v1
kind: Deployment
metadata:
  name: orders
spec:
  replicas: 2
  strategy:
    type: Recreate
  selector:
    matchLabels:
      app: orders
  template:
    metadata:
      labels:
        app: orders
    spec:
      containers:
      - name: orders
        image: ghcr.io/fooddash/orders:2.1.3
        ports:
        - containerPort: 8080
        livenessProbe:
          httpGet:
            path: /health
            port: 8080
  1. Detect the three problems that prevent this, and state how to fix each. [3]
  2. Analyze how your corrected manifest protects users during a rolling update. [2]

(5 marks · CO2 · PO4 · BL4)

(b) In the food-delivery app:

  • users reach the React frontend from outside the cluster on node port 30090
  • the orders API is called only by the frontend’s Nginx proxy, inside the cluster
  • the MySQL database is used only by the orders API
apiVersion: v1
kind: Service
metadata:
  name: web
spec:
  type: ClusterIP
  selector:
    app: web
  ports:
    - port: 80
      targetPort: 80
---
apiVersion: v1
kind: Service
metadata:
  name: orders
spec:
  type: LoadBalancer
  selector:
    app: orders
  ports:
    - port: 80
      targetPort: 8080
---
apiVersion: v1
kind: Service
metadata:
  name: db
spec:
  type: NodePort
  selector:
    app: db
  ports:
    - port: 3306
      targetPort: 3306
      nodePort: 30306
  1. Detect the three problems with how these Services expose the components, and state the fix for each. [3]
  2. Analyze the risk or failure each problem causes. [2]

(5 marks · CO2 · PO4 · BL4)
