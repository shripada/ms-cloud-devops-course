Your first container

Today's goal: run a real web server in a container, prove that it is “just a process”, and clean it up. About 15 minutes.

Why this matters for DevOps

Almost every company you will join ships its software as containers. In placement interviews for Cloud and DevOps roles, one of the first questions is usually: “What is the difference between an image, a container and a VM?” By the end of this page you can answer it, and you will have actually done it, not just read about it.

Three ideas, no more

Image: a package that contains everything needed to run a program: files, binaries, libraries and config. An image never changes once it is built (it is immutable), and it is made of layers. [Docker docs]

Container: a running, isolated process started from an image. [Docker docs] You studied OOP in college, so think of it this way: the image is the class and the container is the object. One image can give you many containers.

Not a VM: a virtual machine boots a complete operating system with its own kernel. A container does not. All containers share the host's kernel. Remember the OS subject: a process is just a program in execution managed by the kernel. That is why containers start in milliseconds and use very little memory. [Docker docs]

One twist on your Mac: macOS does not have a Linux kernel. So Docker quietly runs a small Linux VM in the background, and your containers share that VM's kernel. [Docker Desktop docs]

Do it

  1. Start the nginx web server in the background. This connects port 8080 on your Mac to port 80 inside the container: 
    docker run -d -p 8080:80 --name web nginx
    You don't have the nginx image yet, so Docker first pulls (downloads) it from Docker Hub. Watch the layers download one by one.
  2. Open http://localhost:8080 in your browser. You should see “Welcome to nginx!”. Or run curl localhost:8080 in the terminal.
  3. List running containers: 
    docker ps
  4. Prove that it is just processes: 
    docker top web
    You will see one nginx master process and some worker processes. There is no OS booting up and no init system. It's only nginx.
  5. Refresh the browser once, then read what nginx has printed: 
    docker logs web
  6. Stop the container, then look again: 
    docker stop web
docker ps
docker ps -a
    docker ps shows only running containers. docker ps -a shows all of them, including stopped ones.
  7. Delete the container. The image is not deleted, so the next run will not download it again: 
    docker rm web
docker images
Stretch: run two containers from the same image, one with -p 8081:80 --name a and one with -p 8082:80 --name b. Both work at the same time. That is “one image, many containers”, or one class, many objects. Clean them up after.

Check yourself

Answer before clicking. Getting it wrong first is fine. That struggle is what makes it stay in your head.

1. Which best describes a container?

2. You ran docker run -d -p 8080:80 nginx. What do you type in your browser?

3. After docker stop web, it's missing from docker ps. Where did it go?

4. Interview practice (say it out loud or type it): “What is the difference between an image and a container, and why is a container lighter than a VM?”

Compare with a model answer

An image is an immutable, layered package of everything an app needs. A container is an isolated running process created from that image, and many containers can come from one image. Containers share the host's kernel instead of booting a full OS like a VM, so they are smaller and start almost instantly.
